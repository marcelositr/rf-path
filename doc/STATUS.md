# RF-Path — Project Status

## Current phase

**Phase 3 — SRTM terrain**

## Current state

The Rust foundation and initial geometry/RF primitives are implemented. The project now has a mmap-backed SRTM3 HGT reader with explicit tile selection, big-endian decoding, north-to-south row handling, bilinear interpolation, NoData errors, and an in-memory tile cache.

Deterministic synthetic HGT fixtures are generated by integration tests at runtime; real SRTM data is not committed to the repository. The development-only Python reference layer contains corresponding geographic, RF, and SRTM tile/interpolation calculations.

## Known constraints

- Production implementation is Rust.
- Python reference tooling is development-only and must not become a runtime dependency.
- SRTM data will be supplied locally and must not be committed to the repository.
- No real SRTM fixtures are present yet.
- CLI parsing is currently a structural foundation; full command execution remains pending.
- Synthetic differential vectors intentionally use a deterministic generated HGT surface so Rust and Python can be compared without shipping real SRTM data.
